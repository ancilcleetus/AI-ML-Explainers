Why MSE doesn't work for classification

In the Loss Functions Overview Explainer you learned about MSE — squared error between prediction and truth. A natural first instinct: the network outputs probabilities, the truth is a one-hot vector, why not just use MSE on those? It turns out this fails badly. Two reasons.

Two problems with MSE for probabilities
Problem 1 — Bounded penalty for wrong answers
For a probability between 0 and 1, MSE caps at 1.0 — no matter how confidently wrong. A network predicting P(cat) = 0.01 when the truth is cat receives essentially the same MSE as one predicting 0.5. Cross-entropy has no upper bound: confidently wrong predictions are punished severely.
Problem 2 — Tiny gradients near the wrong answer
The slope of MSE is roughly 2(p − target). When p is very wrong (near 0 with target 1), the slope is barely large enough to learn from. Cross-entropy's slope is −1/p — when p is small, the gradient is huge, so the network learns very fast from its worst mistakes.
The question this explainer answers: What loss function rewards confident correct predictions, catastrophically punishes confident wrong predictions, and pairs naturally with the softmax output of a classifier? That function is cross-entropy, and it comes from information theory.

The information theory intuition

Cross-entropy is not a random formula. It comes from information theory — a precise mathematical framework for measuring surprise. Once you see the connection, the −log(p) shape stops being arbitrary and becomes the only choice that makes sense.

Information content (surprise) of an event

Information theory says: the amount of information in observing an event with probability p is −log(p). The lower the probability, the more surprising the event, and the more information it carries.

I(p) = −log(p)
When the log uses base 2, I(p) is measured in bits. In deep learning we use the natural log (base e) — the units don't change the optimization, only the scale. p = 1 → 0 surprise. p → 0 → infinite surprise.

From surprise to loss — the conceptual leap

Now connect this to neural networks. The model produces a probability distribution over classes. The truth is one specific class. The loss is the surprise of the truth, under the model's distribution:

L = −log(ptrue)
ptrue = probability the model assigned to the correct answer. If the model assigned high probability (near 1) → low surprise → low loss. If the model assigned low probability (near 0) → huge surprise → huge loss.
This is why cross-entropy is the principled choice for classification. It is literally the surprise of the correct answer under the model's predicted distribution — minimising it teaches the model to be unsurprised by the truth.

The three regions of the curve
Near p = 1 — confident right
Loss ≈ 0. The model assigned nearly all probability to the truth. Reward: nothing further to learn from this example.
Near p = 0.5 — coin-flip uncertain
Loss ≈ 0.69 (which is ln 2). The model is hedging. Penalty: moderate — the model needs to be more decisive on this example.
Near p = 0 — confident wrong
Loss → ∞. The model confidently picked the wrong answer. Penalty: unbounded. The gradient is huge (−1/p with small p) — the model will dramatically overhaul its weights to fix this.
The unbounded penalty is by design. A network that confidently mislabels a cat as a plane must change a lot — and the huge gradient ensures it does. This is the opposite of MSE's tiny gradient in the same regime.

Binary cross-entropy

The simplest case: a binary classifier — one output neuron, one true label. The output neuron uses sigmoid (which you saw in the Activation Functions Explainer) to produce a probability between 0 and 1. Cross-entropy then measures the loss based on what the truth was.

L = −[y · log(p) + (1 − y) · log(1 − p)]
y ∈ {0, 1} is the true label. p ∈ (0, 1) is the predicted probability of class 1. When y = 1: only −log(p) survives. When y = 0: only −log(1 − p) survives.
Why both terms — and only one is "active" at a time

If the truth is positive (y = 1), the second term is multiplied by 0 and disappears. Loss = −log(p). High loss if p is low.

If the truth is negative (y = 0), the first term is multiplied by 0 and disappears. Loss = −log(1 − p). High loss if p is high (because then 1 − p is low).

In code — and why _with_logits is preferred
# Standard PyTorch — accepts raw logits directly (preferred) logits = model(x) # shape (B,) loss = F.binary_cross_entropy_with_logits(logits, targets.float()) # If you already applied sigmoid yourself (rarely needed): probs = torch.sigmoid(logits) loss = F.binary_cross_entropy(probs, targets.float()) # NEVER apply sigmoid then call binary_cross_entropy_with_logits — that # would apply sigmoid twice and silently destroy your gradients.
Why the "with logits" version exists: calling sigmoid then BCE separately can overflow for large logits — similarly to the numerical stability issue you saw in the Softmax & Probability Outputs Explainer. The combined version is mathematically equivalent but numerically stable.

Categorical cross-entropy

For multi-class classification (more than 2 classes), the network outputs num_classes logits, softmax converts them to probabilities, and categorical cross-entropy is the loss. This is the loss used in 99% of classification tasks.

L = −Σi yi · log(pi)
y is the one-hot true label vector. p is the softmax output. Sum over all classes.
A beautiful simplification — the sum collapses

The true label y is one-hot — exactly one element is 1, the rest are 0. So all terms in the sum vanish except the one for the true class:

L = −log(ptrue)
Where ptrue is the probability the model assigned to the correct class. This is exactly the surprise of the truth (Section 2). The categorical case reduces to the simple −log(p) form.
The "softmax + cross-entropy" pairing

In the Softmax & Probability Outputs Explainer you learned that pi = ezi / Σ ezj. Substitute that into the loss:

L = −log( eztrue / Σj ezj ) = −ztrue + log(Σj ezj)
This combined form has a beautiful gradient that flows cleanly back through the network. Softmax and cross-entropy are designed for each other.

In PyTorch — F.cross_entropy does both at once
logits = model(x) # shape (B, num_classes) — RAW LOGITS loss = F.cross_entropy(logits, targets) # targets is shape (B,) with class indices (NOT one-hot) loss.backward() # gradients flow back
Common beginner mistake: never apply softmax before F.cross_entropy. It does softmax internally as part of the combined stable computation. Doing it twice silently destroys gradients and the network won't train. Pass raw logits directly.

Cross-entropy in PyTorch — a complete reference

All the patterns covered in this explainer plus the most common production options, in one consolidated code block. Every flag shown here gets used somewhere in real classifier training.

import torch
import torch.nn as nn
import torch.nn.functional as F

# ── Binary classification (Section 4) ──────────────────────────────────
# Logits are raw scores; targets are 0.0 / 1.0 floats.
logits_bin = torch.tensor([1.5, -0.8, 2.1])
targets    = torch.tensor([1., 0., 1.])

bce = F.binary_cross_entropy_with_logits(logits_bin, targets)     # ✓ preferred (stable)

# Module form — drops into nn.Module subclasses
loss_fn = nn.BCEWithLogitsLoss()
bce     = loss_fn(logits_bin, targets)


# ── Multi-class classification (Section 5) ─────────────────────────────
# Logits shape (B, C). Labels are class INDICES, shape (B,) — NOT one-hot.
logits = torch.tensor([[2.0, 0.1, -1.0],
                       [0.5, 1.8, -0.2]])
labels = torch.tensor([0, 1])

ce = F.cross_entropy(logits, labels)                              # ✓ softmax + CE in one call

# Module form
loss_fn = nn.CrossEntropyLoss()
ce      = loss_fn(logits, labels)


# ── Production-grade options you will see in real codebases ────────────

# reduction — how to aggregate the per-example losses
ce_mean = F.cross_entropy(logits, labels, reduction='mean')   # default — single scalar (avg)
ce_sum  = F.cross_entropy(logits, labels, reduction='sum')    # single scalar (total)
ce_none = F.cross_entropy(logits, labels, reduction='none')   # shape (B,) — per-example losses

# weight — per-class weighting for class imbalance
# Boost loss on the rare class so the model doesn't ignore it.
class_weights = torch.tensor([1.0, 3.0, 1.0])         # class 1 is rare → weight 3x
ce_w = F.cross_entropy(logits, labels, weight=class_weights)

# ignore_index — skip specific labels in the loss
# Used in language modelling to skip [PAD] tokens, or in segmentation
# to skip "unlabelled" pixels.
ce_pad = F.cross_entropy(logits, labels, ignore_index=-100)

# label_smoothing — soften the target distribution
# Instead of all probability on the true class, distribute a tiny amount
# to other classes. Helps regularisation and prevents overconfident outputs.
ce_ls = F.cross_entropy(logits, labels, label_smoothing=0.1)


# ── The full training loop — putting it all together ──────────────────
for images, labels in dataloader:
    logits = model(images)
    loss   = F.cross_entropy(logits, labels)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
The two flags you'll meet most often: weight handles class imbalance (medical classifiers, fraud detection); label_smoothing is standard in modern vision and language model training (used in the original Transformer paper, BERT, and Vision Transformer). ignore_index=-100 is the default PyTorch convention for "skip this label" — language modelling tokenisers like Hugging Face pad with -100 specifically so this works out of the box.
