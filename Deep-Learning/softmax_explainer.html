by Ancil Cleetus

The output of a neural network classifier is just a list of raw scores called logits — they can be any real numbers. But to make a confident prediction we need probabilities — values between 0 and 1 that sum to exactly 1. Softmax is the function that turns the first into the second. This explainer takes you through every part of how it works and why it is designed the way it is.

Why we need softmax

A classifier network's last layer produces one number per class. These numbers are called logits. They can be anything — positive, negative, large, small. They are not probabilities. To produce a useful prediction we need to convert them into probabilities.

Concrete example — a 5-class animal classifier

After the forward pass, the network outputs these logits for an image:

Raw logits — what the network actually outputs
Range: any real number. No constraint. Sum: not 1.
Probabilities — what we actually need
Range: [0, 1]. Sum: exactly 1.
What probabilities must satisfy
Requirement 1
Each value between 0 and 1. A probability cannot be negative and cannot exceed 1.
Requirement 2
All values sum to exactly 1. The network must commit to a single distribution.
The question this explainer answers: How do we turn 5 arbitrary real numbers into 5 probabilities that satisfy both requirements? The function that does this is called softmax.

Softmax — what it does mechanically

Softmax does two things, in order:

Step 1 — Exponentiate
Apply e^z to every logit. This makes everything positive (since exp is always positive).
Step 2 — Normalise
Divide each exponentiated value by the sum of all of them. Now they sum to exactly 1.
pi = ezi / Σj ezj
For each class i, the probability pi equals e raised to the i-th logit, divided by the sum of e raised to every logit.

Why softmax is designed this way

Beginners often ask: why exponentiate? Why divide by the sum? Why not just use absolute value, or normalise the logits directly? Each design choice is deliberate.

Question 1 — Why not just normalise the logits directly?

The simplest "fix" would be: divide each logit by the sum of all logits. Try it with logits [3, -2, 1] — the sum is 2:

"probabilities" = [3/2, -2/2, 1/2] = [1.5, -1.0, 0.5]
Doesn't work. One value is above 1, another is negative. Neither is a valid probability. We need a transformation that always produces non-negative results — which leads to exponentiation.
Question 2 — Why exponentiation specifically?

Three properties of e^z make it perfect for this job:

1. Always positive
e^z > 0 for any real z. e^(-100) is tiny but still positive. This guarantees non-negative probabilities.
2. Monotonically increasing
If z₁ > z₂ then e^z₁ > e^z₂. The biggest logit always becomes the biggest probability — softmax never flips the ordering.
3. Amplifies differences
A 1-unit gap in logits becomes a ~2.7× ratio in probabilities (because e^1 ≈ 2.7). A 5-unit gap becomes ~148×. The highest-scoring class wins decisively when the gap is meaningful.
Question 3 — Why does it always sum to exactly 1?

By construction. The denominator is exactly the sum of all numerators, so when you sum all the probabilities, you get the sum of numerators divided by itself:

Σi pi  =  Σi [ ezi / Σj ezj ]  =  (Σi ezi) / (Σj ezj)  =  1
The numerator and denominator are the same sum — they cancel to 1 exactly. This is a guarantee of the math, not an approximation.
A useful property — shift-invariance

Adding the same constant c to every logit produces the identical probability distribution. This is because e^(z+c) = e^z · e^c, and the constant e^c appears in every numerator and the denominator — so it cancels out:

softmax([z1+c, z2+c, ..., zn+c])  =  softmax([z1, z2, ..., zn])
This property is the key to numerical stability — covered in the next section.

The numerical stability trick

In real networks, logits can become large — sometimes hundreds or thousands. The exp function grows extremely fast. e^1000 is approximately 10434 — a number with 434 digits. Even 64-bit floating point cannot represent this; the result becomes +Infinity, and any further computation produces NaN.

The fix — subtract the max logit before exponentiating

From the previous section, adding any constant to every logit doesn't change the result. So we add −max(z) — i.e. we subtract the largest logit from every logit. Now the largest value becomes 0, all others are negative, and e^0 = 1 with all other exp values being < 1. No overflow.

# Numerically stable softmax — the standard implementation def softmax_stable(z): z_shifted = z - z.max() # largest becomes 0 exp_z = torch.exp(z_shifted) # all values now ≤ 1 return exp_z / exp_z.sum() # PyTorch's F.softmax does this automatically probs = F.softmax(logits, dim=-1)
You don't need to subtract the max manually in production code — PyTorch's F.softmax, TensorFlow's tf.nn.softmax, and JAX all do this automatically. But understanding why the trick exists is essential for debugging weird NaN issues and for implementing custom variants of softmax in your own code.

Temperature scaling

Standard softmax has a hidden hyperparameter called temperature (T) that we have been silently using with value 1. Changing T sharpens or flattens the probability distribution — without changing which class wins.

pi = ezi / T / Σj ezj / T
Each logit is divided by T before applying softmax. Standard softmax is the special case T = 1.
The intuition
T < 1 — sharpens (more decisive)
Dividing by a small number amplifies differences between logits. The top class wins more confidently. As T → 0, output approaches one-hot.
T = 1 — standard softmax
Default behaviour. The version everywhere unless temperature is explicitly mentioned.
T > 1 — flattens (more uncertain)
Dividing by a big number shrinks differences. The model becomes "more uncertain" — every class gets closer to equal probability. As T → ∞, output approaches uniform (1/N).

Softmax vs Sigmoid

Softmax is not the only function that produces values between 0 and 1. Sigmoid (which you saw in the Activation Functions Explainer) does the same — but for one number at a time. Beginners regularly use the wrong one. This section makes the choice clear.

The fundamental difference
Sigmoid
σ(x) = 1 / (1 + e−x)
Operates on each output independently. Each output is the probability of that one event being true, regardless of the others.
Softmax
pi = ezi / Σ ezj
Operates on all outputs jointly. The classes compete with each other — increasing one decreases the others — and they always sum to 1.
Which to use — the rule
Single-label classification → Softmax
"What animal is this?" Cat XOR Dog XOR Bird — exactly one is true. The probabilities should sum to 1 because the network has to commit.
Multi-label classification → Sigmoid (one per class)
"Tag this photo." Beach AND Sunset AND People can all be true simultaneously. Each tag is independent. No reason for them to sum to 1.
Binary yes/no → Sigmoid
"Is this email spam?" One output, one probability. Sigmoid is the natural choice.
# Multi-class — softmax over all classes logits = model(image) # shape (5,) — cat/dog/bird/car/plane probs = F.softmax(logits, dim=-1) # sums to 1, "this IS a cat (87%)" # Multi-label — sigmoid per class logits = model(image) # shape (3,) — beach/sunset/people probs = torch.sigmoid(logits) # each independent, can all be high
A surprising connection — sigmoid is a 2-class softmax

Sigmoid is exactly what you get when you apply softmax to two logits, where the second is fixed at 0:

softmax([x, 0])[0] = ex / (ex + e0) = ex / (ex + 1) = 1 / (1 + e−x) = sigmoid(x)
So sigmoid and softmax are not different families — they are the same function family, with sigmoid being the special 2-class case. What really determines which one you use is whether the classes compete (use softmax) or are independent (use sigmoid per class).

Softmax in PyTorch — a complete reference

Everything covered in this explainer in one consolidated code block. Note especially the dim parameter — it is the single most common source of softmax bugs.

import torch
import torch.nn.functional as F

# --- Basic usage — one example, 5 class logits ---
logits = torch.tensor([2.1, 1.5, 0.8, -1.2, -0.5])
probs  = F.softmax(logits, dim=-1)        # shape (5,), sums to 1.0

# --- The dim parameter — the #1 beginner trap -------------------------
# Batched logits have shape (B, num_classes). Softmax must be applied
# across CLASSES (axis 1, or equivalently -1), NOT across the batch.
batch_logits = torch.randn(32, 5)         # 32 examples, 5 classes
probs = F.softmax(batch_logits, dim=-1)   # ✓ each row sums to 1

# WRONG — softmax along the batch axis: each COLUMN sums to 1 across
# examples, which is meaningless for classification.
# probs = F.softmax(batch_logits, dim=0)    ❌

# Rule of thumb: dim=-1 is correct for almost every classifier output.

# --- Numerical stability — automatic in PyTorch -----------------------
# F.softmax already subtracts the max internally (Section 4's trick).
# You do not need to do it yourself.

# --- Log-softmax — pairs with cross-entropy ---------------------------
# When pairing with a loss that takes log(p), compute log(softmax(z))
# in one stable step instead of softmax then log:
log_probs = F.log_softmax(logits, dim=-1)  # stable; log(F.softmax(...)) is not

# --- Temperature scaling — Section 5 ---------------------------------
T = 0.7                                  # T < 1 sharpens, T > 1 flattens
probs = F.softmax(logits / T, dim=-1)

# --- Sampling vs argmax — what to do with the probabilities ----------
predicted = probs.argmax(dim=-1)         # deterministic — top class
sampled   = torch.multinomial(probs, 1)    # stochastic — sample by prob (LM-style)
Why dim=-1? The -1 means "the last axis". For classifier outputs, the last axis is almost always the class axis — whether your tensor is shape (B, C) for a single prediction or (B, T, C) for a sequence of predictions. Writing dim=-1 keeps your code correct as the shape grows. If you omit dim entirely on a 2-D tensor, modern PyTorch raises a warning — older code that did this was silently buggy.
