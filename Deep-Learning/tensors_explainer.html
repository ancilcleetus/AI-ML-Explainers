From numbers to tensors

A tensor is just a multi-dimensional array of numbers. The simplest "tensor" is a single number. Stack a few numbers in a row — you get a vector. Stack rows on top of each other — a matrix. Stack matrices — a 3D tensor. Keep going and you get higher-dimensional tensors. Each step adds one more dimension.

Shape, ndim, and axes

Shape is a tuple telling you the size of the tensor along each axis. ndim is just the number of axes. The axis with index 0 is the outermost, axis 1 is the next, and so on. Together, these three concepts let you describe any tensor precisely.

A shape of (3, 4) means: 3 along axis 0 (3 rows), 4 along axis 1 (4 columns). Total elements = 3 × 4 = 12. A shape of (2, 3, 4) means 2 stacks, each with 3 rows × 4 columns = 24 elements total.

The deep learning axis conventions

In deep learning, axes are not just numbered — each axis has a meaning. The first axis is almost always the batch (how many examples you process together). Other axes carry channels, spatial dimensions, time, or sequence information. These conventions are universal across PyTorch, TensorFlow, and JAX.

Tensor operations

Tensors support three families of operations that show up in every neural network: element-wise (apply a function to each element), reductions (collapse one or more axes), and matrix multiplication (the heart of every layer).

Tying back to the Neuron & Forward Pass Explainer

In the Neuron & Forward Pass Explainer, a single neuron computed z = w₁x₁ + w₂x₂ + w₃x₃ + b — one neuron, three inputs [x₁, x₂, x₃], one output number. With tensors we do the same thing for a whole layer of neurons on a whole batch of inputs in one operation.

What the new symbols mean
B — batch size
How many examples we process at once. In the Neuron explainer, we passed in one input vector. Real training processes many at the same time — typically B = 32 or 64. This is the same "batch axis" you saw in Section 3.
in_features — inputs per example
How many numbers each example has. In the Neuron explainer, in_features = 3 (the three sliders [x₁, x₂, x₃]). For an image flattened to a vector, it could be hundreds or thousands.
out_features — neurons in this layer
How many neurons make up the layer — and therefore how many output numbers per example. The Neuron explainer showed one neuron (out_features = 1). A real layer typically has dozens or hundreds.
The shapes in symbols
# A batch of B inputs, each with `in_features` numbers X = tensor of shape (B, in_features) # Weight matrix: one column per output neuron W = tensor of shape (in_features, out_features) # Bias: one per output neuron b = tensor of shape (out_features,) # A whole layer's forward pass — single operation Z = X @ W + b # shape (B, out_features)
The same thing in runnable PyTorch

A concrete example using the exact dimensions from the Neuron explainer — three inputs per example, one output neuron — but now scaled up to a batch of 32 examples:

import torch import torch.nn as nn # A batch of 32 examples, each with 3 inputs (like the Neuron explainer's sliders) X = torch.randn(32, 3) # shape: (32, 3) # A layer with 3 inputs and 1 output neuron — same as one Neuron explainer neuron layer = nn.Linear(3, 1) # creates W of shape (3, 1) and b of shape (1,) # Forward pass — all 32 examples processed in one tensor operation Z = layer(X) # shape: (32, 1) # Add an activation function and you have one full layer: output = torch.relu(Z) # shape: (32, 1)
What a CPU would do with nested loops over millions of multiplications, a GPU does in a single tensor operation — that is why deep learning runs on GPUs.

Broadcasting

When you add two tensors of different shapes, the framework can sometimes "stretch" the smaller one to match the larger one. This is called broadcasting. It is convenient — but it is also the single biggest source of confusing bugs in deep learning code, because the wrong shapes can sometimes broadcast silently in ways you did not intend.

The two rules — applied right to left
Rule 1 — Equal sizes
Compatible if the dimensions are equal. (3, 4) + (3, 4) ✓
Rule 2 — One side is 1
Compatible if one of the dimensions is 1 — it gets repeated. (3, 4) + (1, 4) ✓

Three real-world broadcasting examples
Adding a bias to every row
Z (32, 10) + b (10,) → (32, 10)
A batch of 32 outputs gets the same bias vector added to every row. This is exactly what happens in every fully connected layer.
Normalising images by per-channel mean
images (B, 3, H, W) − mean (3, 1, 1) → (B, 3, H, W)
The mean has 3 values (one per RGB channel) which broadcasts across every spatial position and every example in the batch.
Outer product — combining row and column vectors
(3, 1) × (1, 4) → (3, 4)
A column vector and a row vector both broadcast, producing a matrix — every column-row pair gets multiplied.

Why everything is a tensor

Now the punchline. Every quantity in a neural network — input, weight, bias, activation, gradient, loss — is a tensor. This is not a coincidence. It is what makes deep learning fast.

The same forward pass — three ways
SCALAR — one neuron, one example
z = w₁x₁ + w₂x₂ + w₃x₃ + b
Three multiplications, three additions. Easy to follow but slow when you have millions of these to do.
VECTOR — one neuron, one example (compact form)
z = w · x + b
Same thing, written as a dot product between two vectors. Cleaner notation.
TENSOR — many neurons, many examples (real deep learning)
Z = X @ W + b
Same thing again — but now computing a whole batch through a whole layer in one operation. This is the form actually used in code.
Why GPUs? A GPU has thousands of small cores designed to multiply matrices in parallel. The tensor formulation lets the GPU do all the multiplications simultaneously. Computing one input at a time would waste the parallelism — computing a whole batch at once uses every core. That is why deep learning runs on GPUs and that is why everything is a tensor.
A small reference for reading shape errors

When PyTorch (or any framework) crashes, the error usually mentions tensor shapes. With the vocabulary from this explainer you can already debug the most common ones.

ErrorWhat it meansHow to debug
size mismatch, m1: [B×K], m2: [J×N] Matrix multiplication: K ≠ J Print x.shape and w.shape; transpose one if needed
expected 4D got 3D Forgot the batch axis Use .unsqueeze(0) to add a batch dimension
cannot broadcast (A,) with (B,) Last dims differ and neither is 1 Reshape one tensor or use .view()
RuntimeError: Tensor must be contiguous Memory layout mismatch (after transpose) Call .contiguous() after transpose
