Basic Image Operations — Resize, Crop, Rotate, Flip — Interactive Explainer ↗
The four geometric operations that appear in every CV pipeline. Resize — changing image dimensions, requires interpolation to invent the new pixel values. Three interpolation methods explained visually — nearest-neighbour (fastest, blocky, the right choice for segmentation masks where each pixel must stay a discrete class label), bilinear (smooth, the default for general use), bicubic (smoothest, slowest, used in high-quality image editing). An interactive comparing the three on the same image at different scales. The aspect-ratio question — when you resize 4032×3024 to 224×224, do you squish (distorts the image but no information lost), centre-crop (preserves aspect ratio but loses corners), or letterbox (preserves everything but adds black bars)? Crop — rectangular region selection, the simplest operation but conceptually loaded since CNN preprocessing pipelines crop almost every image. Centre crop vs random crop (used for data augmentation in training) vs full-image with padding. Rotate — by 90°/180°/270° is lossless (just rearranges pixels), arbitrary angles need interpolation and produce black corners (which you then crop or pad). Flip — horizontal (mirror) and vertical (upside-down); horizontal flip is one of the most useful free data-augmentation techniques (for almost every object class a flipped image is still a valid example), vertical flip is much rarer. PyTorch / OpenCV / PIL references for each operation, plus the torchvision.transforms versions that automatically integrate into training pipelines.

Histograms, Brightness, and Contrast — Interactive Explainer ↗
How to summarise and adjust the intensity distribution of an image. A histogram is a count of how many pixels have each intensity value — for a grayscale image, 256 bins (one per possible value); for RGB, three histograms (one per channel). Why this is the most useful single statistic about an image's quality. An interactive showing four photos (dark/underexposed, bright/overexposed, low-contrast, well-exposed) with their histograms below — the user learns to read the shape. Brightness adjustment as img + offset — shifts the histogram left (darker) or right (brighter) without changing its shape. Contrast adjustment as (img - 128) × factor + 128 — stretches or compresses the histogram around the midpoint. Combined linear adjustment as img × α + β. The clipping issue — when an adjustment pushes values past 255 or below 0, those pixels saturate (information lost permanently). Histogram equalisation as the classical fix for badly-exposed images — redistribute pixel values so the histogram becomes approximately uniform, dramatically improving visibility for low-contrast shots. The mathematics — it's a remapping based on the cumulative distribution function of the original histogram, implemented in 4 lines of NumPy or one OpenCV call (cv2.equalizeHist). An interactive demo — brightness/contrast sliders + an "equalise" button on a deliberately badly-exposed photo. Why this matters for what comes next — hand-crafted features (the next subcategory) are sensitive to brightness and contrast variations, so histogram equalisation is often the first preprocessing step in classical CV pipelines.

Image Smoothing & Blurring — Box, Gaussian, Median, Bilateral Filters — Interactive Explainer ↗
Why we blur images at all — to suppress noise, simplify content before feature extraction, and remove fine details that would distract downstream algorithms. Four classical filters explained with kernel visualisations and live demos. Box filter (the simplest: average a square neighbourhood) — fast but produces visible blocky artifacts. Gaussian blur — same idea but weighted by a 2D Gaussian, producing smoother results and matching the human perception of "blur." Mathematics of the Gaussian kernel — σ controls the spread, and bigger σ means more blur. Median filter — replace each pixel with the median of its neighbourhood; uniquely effective at removing salt-and-pepper noise while preserving edges, because the median ignores extreme values. Bilateral filter — the smart blur: averages neighbours but only those with similar intensity, so it smooths within regions but preserves edges between regions. Worked side-by-side comparison on a noisy photograph showing each filter's signature behaviour. OpenCV API reference (verified May 2026) — cv2.boxFilter, cv2.GaussianBlur, cv2.medianBlur, cv2.bilateralFilter with parameter explanations.

Thresholding & Binarisation — Global, Adaptive, Otsu — Interactive Explainer ↗
Turning a grayscale image into a binary mask — pixels become either 0 or 255 based on whether they exceed a threshold. The foundational operation behind document scanning, object isolation, and morphological pipelines. Global thresholding — pick a single value T and apply it everywhere; works for evenly-lit images but fails when lighting varies. Adaptive thresholding — compute T separately for each pixel using its local neighbourhood, producing clean binarisations of documents and uneven scenes. The mathematics of mean-based vs Gaussian-weighted local thresholds. Otsu's method — automatically pick the optimal global T by minimising intra-class variance; an elegant algorithm that requires no parameters and works on bimodal-histogram images. Live demo: a slider for global T showing how mask coverage changes, plus side-by-side comparisons of adaptive and Otsu thresholding on a poorly-lit document photo. OpenCV API reference (verified May 2026) — cv2.threshold (global, Otsu) and cv2.adaptiveThreshold (mean and Gaussian methods) with parameter explanations.

Edge Detection — Sobel, Scharr, Laplacian, Canny — Interactive Explainer ↗
Edges are where brightness changes rapidly. Detecting them is one of the oldest CV problems and a building block for everything from feature descriptors to neural network first-layer activations. Image gradients explained — the partial derivatives ∂I/∂x and ∂I/∂y as convolutions with small kernels. Sobel operator — the classic 3×3 derivative kernels with their characteristic shape; how to compute gradient magnitude and direction. Scharr operator — an improved variant of Sobel with better rotational symmetry. Laplacian operator — second-order derivative (sum of ∂²I/∂x² + ∂²I/∂y²), captures edges of both polarities in one shot. The Canny edge detector — the multi-stage algorithm that turned edge detection from "compute gradient magnitude" into a complete pipeline: Gaussian smoothing, gradient computation, non-maximum suppression, double thresholding, hysteresis tracking. Each Canny stage visualised live on a worked image. Live demos: kernel-visualiser showing what each operator does to a step edge, plus a Canny threshold slider showing how the hysteresis range controls edge thickness and noise. OpenCV API reference (verified May 2026) — cv2.Sobel, cv2.Scharr, cv2.Laplacian, cv2.Canny with parameter explanations.

Contour Detection & Analysis — Interactive Explainer ↗
Once an image is binarised, the next question is: where are the connected regions? Contour detection finds the outline of each connected component as a sequence of pixel coordinates. The basic algorithm — border-following (Suzuki's algorithm) explained with a step-through animation on a small binary image. Contour hierarchy — outer contours can have holes which are inner contours; how OpenCV represents the parent-child tree. Practical measurements you compute from a contour: area (using the shoelace formula), perimeter, centroid (first moment), bounding box, minimum-enclosing circle, minimum-area rotated rectangle. Contour approximation — replacing a noisy contour with a polygon (Douglas-Peucker algorithm); the trade-off between fidelity and simplicity. Shape descriptors derived from contours: aspect ratio, extent (contour area / bounding box area), solidity (contour area / convex hull area), circularity (4πA / P²). Use cases: counting objects in microscopy images, measuring objects in industrial inspection, finding the orientation of elongated shapes. Morphological Operations — Erosion, Dilation, Opening, Closing — Interactive Explainer ↗
Morphological operations work on binary or grayscale images using a small "structuring element" (typically a 3×3 or 5×5 shape) that probes the image. The two atomic operations: erosion shrinks foreground regions (a pixel stays white only if all neighbours under the structuring element are white) and dilation grows them (a pixel becomes white if any neighbour is white). Visual intuition: erosion eats away at edges, dilation fills in gaps. Compound operations built from these: opening (erosion then dilation) removes small noise specks while preserving large regions, closing (dilation then erosion) fills small holes inside regions. Morphological gradient (dilation minus erosion) — produces an outline of objects. Top-hat (image minus opening) and black-hat (closing minus image) for highlighting bright or dark features against varying backgrounds. Practical uses: cleaning up thresholded images before contour detection, separating touching objects in segmentation pipelines, isolating writing on scanned documents. Live demo: a 5×5 structuring element selector with sliders, watching the result on a binary image with both small noise and large regions. OpenCV API reference (verified May 2026) — cv2.erode, cv2.dilate, cv2.morphologyEx with operation flags (MORPH_OPEN, MORPH_CLOSE, MORPH_GRADIENT, MORPH_TOPHAT, MORPH_BLACKHAT), cv2.getStructuringElement.

Fine-Grained Classification — Distinguishing Similar Categories — Interactive Explainer ↗
Standard image classification distinguishes broad categories — cat vs dog vs car. Fine-grained classification distinguishes between very similar categories within the same superclass — Siberian Husky vs Alaskan Malamute, Anna's Hummingbird vs Costa's Hummingbird, 2018 Honda Civic vs 2019 Honda Civic. Why this is hard: inter-class differences are subtle (a slightly different beak shape, a small change in tail feathers), intra-class variations are large (different poses, lighting, ages), and labelled data is expensive because experts are needed to annotate. Datasets that defined the field: CUB-200-2011 (200 bird species), Stanford Cars (196 car models), Stanford Dogs (120 breeds), iNaturalist (10K+ species), Food-101 (101 food categories). Methods overview. Attention-based approaches — make the model focus on discriminative parts (heads, wings, wheels) automatically; landmark architectures include Bilinear-CNN (compute the outer product of features from two networks to capture second-order interactions), Recurrent Attention Models, and modern attention-based ViTs. Part-based approaches — explicitly model object parts and aggregate features; useful when expert knowledge identifies the relevant body parts. Loss-function approaches — softmax variants like CutMix, MixUp, label smoothing that handle the high-confusion problem. Modern methods: ViTs pretrained on iNaturalist transfer well to fine-grained tasks; large-scale contrastive learning (CLIP) gives surprisingly strong fine-grained features out of the box. Live demo: attention-heatmap visualisation showing which parts of a bird image the model focuses on when distinguishing it from a similar species; per-class confusion matrix highlighting the most-confused pairs.

Crowd Counting & Density Estimation — When Detection Fails on Density — Interactive Explainer ↗
Sometimes you don't want to detect individual objects — you want to count them. When a scene contains hundreds or thousands of small, overlapping, partially-visible instances (a stadium crowd, a flock of birds, ants on a leaf, cells in a microscope), object detection fails because the objects are smaller than the detector's receptive field and heavily occluded. Density estimation takes a different approach: predict a per-pixel density map where each pixel's value is the local expected count, then integrate to get the total. The supervision trick that makes this work: ground-truth annotations are just centroids (a list of (x, y) points where objects are located), but you train against a Gaussian-blurred density map by placing a small Gaussian at each centroid. The σ of the Gaussian is the only hyperparameter and can be tuned per dataset. Landmark architectures: MCNN (Multi-Column CNN, Zhang et al. 2016) — multiple parallel CNNs with different receptive-field sizes to handle scale variation; CSRNet (2018) — uses dilated convolutions to capture larger context without downsampling; P2PNet (2021) — predicts a point set directly with a transformer, often the strongest modern baseline. Metrics: MAE (Mean Absolute Error in count), MSE, GAME (Grid Average Mean Error) which evaluates count locally not just globally. Practical considerations: extreme scale variation (people far from camera are tiny pixels, people near are huge), perspective effects, and how to evaluate on partially-visible edges. Classical Tracking — Kalman Filter & Hungarian Algorithm — Interactive Explainer ↗
Before deep learning, tracking was a beautiful application of classical probabilistic methods. The Kalman filter — predict the next position of each track using a constant-velocity motion model, then correct using the new measurement; the optimal linear estimator under Gaussian noise assumptions. The mathematics: state vector (position + velocity), state-transition matrix, observation matrix, process and measurement noise covariances. Step-by-step worked example on a tracked point with noisy observations. The Hungarian algorithm — solving the assignment problem of matching new detections to existing tracks; given an N×M cost matrix (typically distance between predicted track position and detection), find the optimal assignment in polynomial time. The combination — predict track positions with Kalman, score against new detections, assign with Hungarian, update with Kalman — is the backbone of every modern MOT tracker. Why it still matters in the deep-learning era: every modern tracker (SORT, DeepSORT, ByteTrack) uses this loop, just with smarter cost functions. Liveness Detection & Anti-Spoofing — Interactive Explainer ↗
The forgotten layer of face recognition: distinguishing a real face from a presentation attack (printed photo, video replay, 3D mask). Without liveness, biometric authentication is trivially defeated. Attack types — print attack (paper photo), replay attack (video on a phone), 3D mask, deep-fake video; each has different telltale signatures. The fundamental defence categories: passive detection (analysing the input image/video for spoof clues) vs active detection (challenge-response, e.g. "blink now," "turn head left"). Passive approaches: texture analysis (printed photos lack the micro-texture of real skin), spectral analysis (screens emit different reflectance), motion analysis (real faces have subtle micro-movements), depth or thermal cues (require specialised hardware). Deep-learning passive detectors — CNN classifiers trained on spoof vs live datasets (CASIA-SURF, CelebA-Spoof, SiW-M). What is Image Retrieval? — Visual Search at Scale, Metrics (mAP, Recall@K) — Interactive Explainer ↗
Given a query image, return the most similar images from a gallery of millions or billions. The foundational task behind reverse-image search (Google Images, TinEye), product search ("shop the look"), duplicate and near-duplicate detection, content moderation, and trademark protection. Why it's distinct from classification: there's no fixed set of classes. The gallery is open-set and grows constantly; the task is similarity ranking, not categorical labelling. The standard two-phase pipeline: (1) offline indexing — pass every gallery image through an embedding network, store the embedding vectors in a search index; (2) online query — embed the query, find the top-K nearest neighbours by cosine similarity or L2 distance. Metrics. mAP (mean Average Precision) — averages precision across recall levels; the standard ranking metric. Recall@K — fraction of relevant items in the top K; matches how users interact with search results. nDCG (normalised Discounted Cumulative Gain) — weights earlier-ranked relevant items more. Standard benchmarks: Oxford / Paris (landmark retrieval), Stanford Online Products (product search), DeepFashion, Google Landmarks v2 (the modern large-scale benchmark with 5M images and 200K landmarks). Image Embeddings for Retrieval — CNN & ViT Feature Extraction — Interactive Explainer ↗
How to turn an image into a fixed-length vector that captures its visual content. The standard trick: take a pretrained classification network and use the features from the second-to-last layer (before the final classification head) as the embedding. A ResNet-50 produces a 2048-D vector; a ViT-B/16 produces a 768-D vector. Why this works at all: a network trained to discriminate between 1000 ImageNet classes learns features that generalise to other distinctions; cosine similarity between these features correlates well with human-judged image similarity. Pooling strategies — global average pooling (the standard), R-MAC (Regional Maximum Activation of Convolutions, focuses on salient regions), GeM (Generalised Mean) pooling with a learnable exponent. Whitening — PCA-whitening of embeddings removes correlations and dramatically improves retrieval performance; the small post-hoc trick that's often the difference between mediocre and good results. Dimensionality reduction — going from 2048-D to 256-D via PCA preserves most of the retrieval signal while making search 8× faster and 8× cheaper to store. Worked example: extract embeddings from ResNet-50 for a small gallery, compute pairwise cosine similarities, visualise the resulting similarity matrix as a heatmap and the embedding space via t-SNE. The key insight to internalise: every modern retrieval system is some variation on "pretrained network → pool → reduce dimension → cosine similarity."

Pretraining Strategies for Retrieval — Contrastive Learning, Metric Learning, CLIP — Interactive Explainer ↗
Off-the-shelf classification networks give reasonable embeddings, but networks pretrained specifically for similarity give much better ones. Approximate Nearest-Neighbour Search & Vector Databases — FAISS, Milvus, HNSW — Interactive Explainer ↗
Once you have embeddings, you need to find similar ones fast. Brute-force nearest-neighbour search scales as O(N) where N is the gallery size — fine for thousands of items, prohibitive at millions or billions. Approximate Nearest-Neighbour (ANN) search trades a small recall loss for orders-of-magnitude speedup. Three families of methods. Tree-based — KD-trees, Ball trees; work well in low dimensions but degenerate to brute-force in the high-dimensional embedding spaces we actually use. Hash-based — Locality-Sensitive Hashing (LSH), various variants. Cheap to build, queryable in constant time, but quality degrades with dimensionality. Graph-based — HNSW (Hierarchical Navigable Small World), the modern state-of-the-art. Builds a multi-layer proximity graph; query navigates from coarse layer to fine layer, visiting only a tiny fraction of the gallery. Quantisation — Product Quantisation (PQ) compresses each embedding into a few bytes; combined with HNSW, the result is the IVF-PQ index used by FAISS for billion-scale search. Vector databases — production systems built around these indices: FAISS (Meta's foundational library), Milvus, Qdrant, Pinecone, Weaviate. The features they add beyond raw indices: persistence, replication, filtering by metadata, hybrid search (combining vector similarity with keyword search), CRUD operations. Practical recommendations: when to use which library, latency budgets, recall-vs-speed trade-offs visualised. Live demo: a small gallery search comparing brute-force vs IVF-PQ vs HNSW, showing the recall-speed trade-off as you tune the index hyperparameters.

What is Visual Anomaly Detection? — The Imbalanced-Label Problem, ROC-AUC, PR-AUC — Interactive Explainer ↗
Anomaly detection identifies images (or pixels) that don't match the normal distribution seen during training. The defining characteristic: extreme label imbalance — usually all training data is normal, and anomalies are either entirely unseen at training time or vanishingly rare. Why standard classification fails: there's no "anomaly class" with enough examples to learn; anomalies in deployment are open-set (new defect types that didn't exist in any training set). Use cases. Industrial inspection — PCB defects, fabric flaws, metal surface inspection, food quality control. Medical imaging — lesion detection, screening for rare diseases. Surveillance — unusual events in video footage. Asset inspection — solar panel cracks, pipeline corrosion. The image-level vs pixel-level distinction: "is this image anomalous?" (binary classification) vs "where in this image is the anomaly?" (segmentation-style output). Both matter in industrial inspection. Metrics for the imbalanced setting. ROC-AUC — robust to imbalance but optimistic on highly-imbalanced data. PR-AUC (precision-recall curve area) — better for rare-anomaly cases. Per-pixel metrics for pixel-level anomaly localisation: AUROC over pixels, AP, PRO (Per-Region Overlap). Reconstruction-Based Methods — Autoencoders, GANs, Diffusion for Anomaly Detection — Interactive Explainer ↗
The first major family of methods. The core idea: train a model to reconstruct normal images perfectly; at inference, anomalous images will be reconstructed poorly because the model never learned their patterns. The reconstruction error then becomes the anomaly score. Autoencoder-based methods — train a convolutional autoencoder on normal images only, measure pixel-wise reconstruction error at test time. Variants: variational autoencoders (VAE), denoising autoencoders. Limitations: autoencoders often generalise too well, reconstructing anomalies almost as accurately as normal images (the "identity shortcut" problem). GAN-based methods — AnoGAN, GANomaly. Train a GAN on normal images; at test time, find the latent vector whose generated image best matches the input, and the reconstruction error is the anomaly score. The expensive iterative inversion at test time was a major limitation, mostly solved by GANomaly's encoder-decoder-encoder architecture. Diffusion-based methods — the most recent breakthrough. Trained on normal images, a diffusion model can reconstruct "the normal version" of an anomalous image; the difference between input and reconstruction localises the anomaly precisely. Landmark methods: AnoDDPM, DDAD. Practical considerations: training stability, computational cost of inference (especially for diffusion), and how to choose the right reconstruction-loss formulation. Live demo: side-by-side reconstruction outputs of an autoencoder, GAN, and diffusion model on a normal vs anomalous test image, with the per-pixel anomaly map visualised.

Feature-Based Methods — PaDiM, PatchCore, SPADE — Interactive Explainer ↗
The second major family — and the current state-of-the-art for industrial anomaly detection. The insight: instead of training a model to reconstruct images, use a pretrained network (typically ImageNet-trained ResNet or Wide-ResNet) to extract features from normal images, then model the distribution of those features. Anomalous patches will have features that fall outside the distribution. SPADE (Cohen and Hoshen 2020) — use a pretrained backbone, store features from every patch of every normal training image as a memory bank; at test time, find the nearest neighbour distance from each test-image patch to the memory bank. The simple-but-effective approach that beat all the deep-learning approaches of its time. PaDiM (Defard et al. 2020) — instead of storing all features, model each spatial location's features as a multivariate Gaussian fitted on normal data; at test time, compute Mahalanobis distance. Smaller memory footprint, very fast inference. PatchCore (Roth et al. 2022) — the current default. SPADE-style memory bank but with a clever coreset subsampling that keeps memory tractable, plus locally-aware feature aggregation. Achieves near-perfect performance on the MVTec-AD industrial benchmark. Why these methods work so well: a pretrained ImageNet model produces features that are already discriminative for fine-grained differences; the only thing missing is calibration to the specific domain, which the feature distribution modelling provides. Self-Attention Intuition — Interactive Explainer ↗
The mechanism that makes Vision Transformers possible — built from zero for someone who's only ever seen convolutions. The motivation framed first — CNNs have local receptive fields (a 3×3 filter only sees its immediate neighborhood; you need many layers to "see" the whole image); what if every position in the image could attend to every other position from layer 1? That's self-attention. The Q / K / V mechanism explained as a soft database lookup — each token (image patch, in our case) creates a query ("what am I looking for?"), every other token creates a key ("what do I represent?") and a value ("what information do I carry?"). Attention weights = softmax(Q·Kᵀ / √d) — scaled dot product, where √d prevents the softmax from saturating in high dimensions (worked example showing how the variance scales). An interactive grid-of-patches demo where the user clicks a patch and sees the attention weights to every other patch visualised as opacity. Multi-head attention as running this in parallel with different learned projections, capturing different relationships. The output as a weighted sum of values. Computational cost — O(N²) in sequence length, a key trade-off vs CNN's O(N).

DETR & Successors — Transformer-Based Detection — Interactive Explainer ↗
Object detection without anchors, without NMS, end-to-end with a transformer. DETR (Carion et al., 2020) as the conceptual leap — a CNN backbone produces feature maps, those are fed into a transformer encoder-decoder, the decoder uses N "object queries" (learnable tokens, one per potential output box) that attend to image features. Each query directly produces a (class, box) prediction — no anchors, no NMS, no proposal stage. The bipartite matching loss — the predictions are matched to ground-truth boxes using the Hungarian algorithm so each ground truth is assigned to exactly one prediction; everything else is "no object." An animated demo showing query-to-image attention maps converging during training. DETR's significance — a fundamentally new detection paradigm. Its limitations — slow convergence (500 epochs!), worse small-object performance than YOLO. Deformable DETR (2021) as the fix — attention only attends to a small set of learned reference points, dramatically faster convergence. RT-DETR (2023) — real-time DETR variants that finally caught up to YOLO on speed-vs-accuracy. The set-prediction paradigm summarised.

SegFormer & Mask2Former — Transformer-Based Segmentation — Interactive Explainer ↗
Two important transformer-based segmentation models with different design philosophies. SegFormer (NeurIPS 2021) — the simple hierarchical approach: hierarchical transformer encoder (like Swin from #31, but with overlapping patches and no positional encoding — learned positional information emerges from a Mix-FFN), lightweight all-MLP decoder that fuses multi-scale features with no extra attention. Why removing the complex decoder works — most segmentation gain is from a strong encoder; the decoder just needs to fuse and upsample. The B0–B5 family from edge to server. Mask2Former (CVPR 2022) — the unified paradigm: one architecture for semantic, instance, AND panoptic segmentation. The key idea — instead of per-pixel classification, predict a set of mask queries (similar to DETR's object queries), each producing a class prediction + a binary mask. Masked attention restricts attention to the foreground of the predicted mask, dramatically improving convergence. A side-by-side visualisation of how the same Mask2Former handles all three segmentation tasks just by changing what queries mean. The unification trend in modern CV — one backbone, many tasks.

Self-Supervised ViTs — DINO & DINOv2 — Interactive Explainer ↗
Learning visual representations without labels — and getting object discovery for free. The motivation — ImageNet's 1.3M labels are expensive; the internet has billions of unlabeled images. Can we use them? DINO (Caron et al., 2021) — a self-distillation framework: two networks (student and teacher — same architecture, teacher's weights are a slow exponential moving average of the student's), fed two different augmentations of the same image, trained so the student matches the teacher's output. No labels needed. The crucial emergent property — DINO's attention maps on the [CLS] token spontaneously segment objects from background; a visualisation shows DINO discovering dogs and cars without ever being told what those are. The implications for object discovery and zero-shot segmentation. DINOv2 (Meta, 2023) — scaled to 142M curated images, multi-resolution training, distillation from ViT-g, producing universal vision features that work across classification, segmentation, depth estimation, and retrieval without task-specific fine-tuning. DINOv2's role as the de-facto vision backbone for downstream tasks in 2024–2026. The "vision foundation model" idea preview for Explainer #38.

Masked Image Modeling — MAE & BEiT — Interactive Explainer ↗
The "BERT for vision" approach to self-supervised pretraining. The masked-language-modeling analogy — BERT masks 15% of words in a sentence and trains the model to predict them; can we mask image patches and predict them? BEiT (Microsoft, 2021) — the first viable answer: tokenise image patches using a discrete tokenizer (like a VQ-VAE codebook), mask 40% of patches, predict the discrete token IDs of the masked patches. A worked example showing the masking and the per-patch token prediction. MAE (He et al., 2022) — the simpler, dominant version: mask 75% of patches (vastly more than NLP's 15% — images are more redundant), feed only the 25% visible patches to a heavy ViT encoder (computational savings!), then use a lightweight decoder to reconstruct the raw pixel values of the masked patches. Side-by-side reconstructions showing what MAE recovers from 25% visible. Why high mask ratios are necessary and why pixel-reconstruction loss works. The result — ViTs pretrained with MAE outperform supervised ImageNet pretraining when fine-tuned downstream. MAE's lasting impact on the SSL paradigm and its emergence as the default ViT pretraining recipe.

CLIP — Contrastive Language-Image Pretraining — Interactive Explainer ↗
The model that connected vision and language at internet scale, and gave us zero-shot image classification. The setup — 400M image-text pairs scraped from the web, two encoders (a ViT for images, a transformer for text), trained with contrastive loss: in a batch of N image-text pairs, the dot product of the i-th image embedding with the i-th text embedding should be high, and with every other text embedding should be low. An interactive batch-similarity-matrix visualisation showing the diagonal lighting up during training. The InfoNCE loss made concrete. Why this is powerful — at inference, you can classify an image against arbitrary class names by phrasing them as "a photo of a [class]" and picking the highest similarity. A live zero-shot classification demo where the user types arbitrary class candidates (no training data needed) and CLIP classifies an image among them. CLIP's downstream impact — it's the text-image bridge powering Stable Diffusion's text prompts, used as a frozen scoring model for image generation evaluation, and the conceptual ancestor of every vision-language model that followed.

BLIP & Flamingo — Vision-Language Models — Interactive Explainer ↗
Beyond CLIP's zero-shot classification — models that can generate captions, answer questions about images, and do few-shot multimodal in-context learning. BLIP (Salesforce, 2022) — a unified vision-language pretraining framework with three losses: image-text contrastive (like CLIP), image-text matching (binary "do they match?"), image-conditioned language modeling (caption generation). Why this multi-objective recipe produces a model that can both understand and generate. A live BLIP demo — upload an image → generated caption + Q/A on the image. BLIP-2 as the modern efficient version — connect a frozen image encoder + frozen LLM via a small trainable "Q-Former" bridge, dramatically reducing training cost. Flamingo (DeepMind, 2022) — few-shot multimodal in-context learning: feed the model a sequence of image-text-image-text examples in the prompt, then a new image, and it answers in the style of the examples without any fine-tuning. The cross-attention "Perceiver Resampler" that connects vision to a frozen language model. A worked example walking through a 2-shot VQA prompt. The lineage that led to GPT-4V and Claude with vision.

Segment Anything — SAM 1 → SAM 2 → SAM 3 — Interactive Explainer ↗
The Meta vision-foundation-model trilogy and its progression to open-vocabulary, video-aware concept segmentation. SAM 1 (Meta, 2023) — promptable image segmentation: user gives a click, box, or rough mask; SAM produces a precise segmentation mask for whatever object that prompt points at. Architecture — heavy ViT image encoder + lightweight prompt encoder + mask decoder. The SA-1B dataset (11M images, 1.1B masks, the largest segmentation dataset ever). The "segment anything" zero-shot capability demoed interactively. SAM 2 (2024) — extends SAM to video: the same prompt-based interface, plus mask propagation across frames using a transformer memory mechanism. Click an object in frame 1, get the tracked mask for the entire video. SAM 3 (2025–2026) — the open-vocabulary leap, Promptable Concept Segmentation. Instead of "this object" (a point), you say "all yellow school buses" (a text concept) and SAM 3 detects, segments, AND tracks every instance across an image or video. The hybrid architecture — a DETR-style detector + the SAM 2 tracker, both built on a shared vision-language Perception Encoder. A "presence head" that decides whether the concept exists at all before localising it. SAM 3 as the convergence point of everything in this roadmap — CNN + transformer backbones, transformer detection, transformer segmentation, vision-language alignment, self-supervised pretraining, video understanding. The natural endpoint for the CV journey.
