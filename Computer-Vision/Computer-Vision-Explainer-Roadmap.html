Colour — RGB, BGR, HSV, and Grayscale — Interactive Explainer
Why each pixel carries three numbers instead of one. The biology — human eyes have three types of cone cells sensitive to roughly red, green, and blue wavelengths; the RGB representation matches how we see. The 8-bit-per-channel convention (0–255 per channel, 256³ ≈ 16.8 million representable colours), why we often normalise to 0.0–1.0 floating-point for neural network input. An interactive RGB colour picker showing how (R, G, B) triples produce colours, with worked examples — pure red = (255, 0, 0), white = (255, 255, 255), the colour of a sunset ≈ (255, 100, 50). Then the gotcha that bites every beginner — OpenCV reads images in BGR order while every other Python library uses RGB. A side-by-side demo showing the same image displayed correctly (RGB) vs the cyan-and-orange disaster you get when you forget to convert. Why this happened historically and how to detect-and-fix the bug in code (cv2.cvtColor(img, cv2.COLOR_BGR2RGB)). Then HSV (Hue–Saturation–Value) as an alternative colour space — an interactive HSV picker, why HSV is sometimes more useful for colour-based segmentation. Grayscale as the one-channel reduction — when you'd convert (most classical CV algorithms operate on intensity only, many object-detection features are colour-invariant). The conversion formula gray = 0.299·R + 0.587·G + 0.114·B and why green has the largest weight (human eyes are most sensitive to green). PyTorch / OpenCV / PIL references for each operation.

Images as NumPy Arrays — Interactive Explainer
The conceptual bridge between "an image" and "data your code can manipulate." An RGB image is a NumPy array of shape (H, W, 3); a grayscale image is shape (H, W). The dtype is typically uint8 (8-bit unsigned integers, 0–255) for storage and float32 for neural-network input. The indexing rules walked through with interactive examples — img[y, x] returns one pixel as a length-3 array, img[y:y+h, x:x+w] returns an (h, w, 3) region (a crop), img[:, :, 0] returns just the red channel as a 2D array. Why NumPy is the right abstraction for image work — vectorised operations are 100–1000× faster than Python loops, and pretty much every CV library accepts NumPy arrays as input/output. A worked-example interactive — take a small image, apply a sequence of NumPy operations (crop a 100×100 region, flip horizontally with img[:, ::-1], brighten by 30 with np.clip(img + 30, 0, 255), swap red and blue channels with img[:, :, [2, 1, 0]]) and watch each step's output. The data-type pitfall — uint8 + uint8 wraps around (255 + 30 = 29, not 285), which is why we use np.clip or convert to int16 first. A PyTorch reference showing how transforms.ToTensor() converts the (H, W, C) uint8 NumPy array to a (C, H, W) float32 PyTorch tensor with values in 0.0–1.0 — the format every PyTorch CNN expects.

Basic Image Operations — Resize, Crop, Rotate, Flip — Interactive Explainer
The four geometric operations that appear in every CV pipeline. Resize — changing image dimensions, requires interpolation to invent the new pixel values. Three interpolation methods explained visually — nearest-neighbour (fastest, blocky, the right choice for segmentation masks where each pixel must stay a discrete class label), bilinear (smooth, the default for general use), bicubic (smoothest, slowest, used in high-quality image editing). An interactive comparing the three on the same image at different scales. The aspect-ratio question — when you resize 4032×3024 to 224×224, do you squish (distorts the image but no information lost), centre-crop (preserves aspect ratio but loses corners), or letterbox (preserves everything but adds black bars)? Crop — rectangular region selection, the simplest operation but conceptually loaded since CNN preprocessing pipelines crop almost every image. Centre crop vs random crop (used for data augmentation in training) vs full-image with padding. Rotate — by 90°/180°/270° is lossless (just rearranges pixels), arbitrary angles need interpolation and produce black corners (which you then crop or pad). Flip — horizontal (mirror) and vertical (upside-down); horizontal flip is one of the most useful free data-augmentation techniques (for almost every object class a flipped image is still a valid example), vertical flip is much rarer. PyTorch / OpenCV / PIL references for each operation, plus the torchvision.transforms versions that automatically integrate into training pipelines.

Histograms, Brightness, and Contrast — Interactive Explainer
How to summarise and adjust the intensity distribution of an image. A histogram is a count of how many pixels have each intensity value — for a grayscale image, 256 bins (one per possible value); for RGB, three histograms (one per channel). Why this is the most useful single statistic about an image's quality. An interactive showing four photos (dark/underexposed, bright/overexposed, low-contrast, well-exposed) with their histograms below — the user learns to read the shape. Brightness adjustment as img + offset — shifts the histogram left (darker) or right (brighter) without changing its shape. Contrast adjustment as (img - 128) × factor + 128 — stretches or compresses the histogram around the midpoint. Combined linear adjustment as img × α + β. The clipping issue — when an adjustment pushes values past 255 or below 0, those pixels saturate (information lost permanently). Histogram equalisation as the classical fix for badly-exposed images — redistribute pixel values so the histogram becomes approximately uniform, dramatically improving visibility for low-contrast shots. The mathematics — it's a remapping based on the cumulative distribution function of the original histogram, implemented in 4 lines of NumPy or one OpenCV call (cv2.equalizeHist). An interactive demo — brightness/contrast sliders + an "equalise" button on a deliberately badly-exposed photo. Why this matters for what comes next — hand-crafted features (the next subcategory) are sensitive to brightness and contrast variations, so histogram equalisation is often the first preprocessing step in classical CV pipelines.

Transfer Learning & Fine-Tuning — Interactive Explainer ↗
The single most practically important technique in modern CV — using a network someone else trained as your starting point. Why transfer learning works: the feature hierarchy from Explainer #5 means early layers learn generic features (edges, textures, simple patterns) that transfer across tasks, and only later layers are task-specific. An interactive visualiser showing activations of the same image across layers of a pretrained network, with early layers looking similar across very different inputs. The three practical strategies with decision rules — feature extraction (freeze backbone, train only a new head — for very little data); fine-tuning the head + last block (for moderate data); full fine-tuning with a small learning rate (for substantial data). The learning-rate-by-layer-group pattern (smaller LR for earlier layers, larger for the new head). When transfer learning fails (target domain very different from source). Full PyTorch reference with torchvision.models, requires_grad=False, replacing the final fc layer, and configuring parameter groups in the optimizer.

VGG & Inception / GoogLeNet — Interactive Explainer ↗
Two contrasting design philosophies that defined the post-AlexNet era. VGG (2014) — the depth-via-simplicity school: stack many small 3×3 convolutions, double the channel count every time you pool. An interactive visualiser showing how the receptive field grows as you stack 3×3 convs (two 3×3s = one 5×5 receptive field but with fewer parameters and an extra non-linearity). The depth-vs-width trade-off (callback to DL #19). Then Inception / GoogLeNet (2014) — the parallel-paths school: the Inception module with parallel 1×1, 3×3, 5×5 conv branches and pooling, concatenated along the channel axis. The 1×1 convolution as a "bottleneck" for channel-wise dimensionality reduction with the parameter-savings math explained visually. Auxiliary classifiers in deep networks. Why GoogLeNet had 22 layers but fewer parameters than 8-layer AlexNet. The lasting influence of both — VGG's 3×3-everywhere as the standard kernel size, and Inception's 1×1-as-bottleneck appearing in ResNet and beyond.

ResNet — Residual Connections — Interactive Explainer ↗
The single most important CNN architectural innovation — what made networks deeper than 30 layers actually train. The depth-vs-trainability problem: empirically, plain stacked CNNs got worse past ~20 layers, not just hard to train (callback to DL #14 Vanishing & Exploding Gradients). The residual block — instead of learning H(x), learn F(x) = H(x) − x, so the layer learns the residual and the identity mapping is free. An interactive comparison of plain vs residual block training curves on a 50-layer network. Why this fixes gradient flow — gradients can shortcut through skip connections, so the effective gradient at early layers stays large (worked back-of-envelope calculation). The bottleneck block (1×1 → 3×3 → 1×1) that ResNet-50 and deeper use. DenseNet as a related idea and why ResNet won. The downstream impact — residual connections appear in every transformer block too, making this the bridge to Category 6.

MobileNet & EfficientNet — Interactive Explainer ↗
Architectures designed when compute and battery are tight. The mobile-deployment problem framed — 1B+ FLOPs is fine on a server, prohibitive on a phone. MobileNet's depthwise separable convolution: factor a standard conv into a depthwise conv (one filter per channel) followed by a 1×1 pointwise conv (mixes channels). An interactive visualiser comparing the FLOPs and parameter count of a standard conv vs a separable conv at varying input sizes, with the ~8–9× savings on a typical layer made concrete. MobileNetV2's inverted residual + linear bottleneck. EfficientNet's compound scaling — instead of scaling just depth (VGG) or width (Wide ResNet) or resolution alone, scale all three by carefully-chosen powers of a single coefficient φ. An interactive slider showing how depth/width/resolution all grow together along the Pareto-optimal frontier. EfficientNet-B0 through B7 as the same architecture at different φ values. When to use each. Forward pointer — efficient ViTs in Explainer #32 use similar tricks.

Fully Convolutional Networks (FCN) — Interactive Explainer ↗
The first end-to-end pixel labelling network, and the operations it introduced that still matter. The core insight (Long et al., 2015) — replace the fully-connected classifier head with 1×1 convolutions so the network produces a spatial output map instead of a single label vector. A side-by-side visualisation: classification CNN outputs a vector → FCN outputs a heatmap, same backbone. The problem this creates — many pools and strided convs → output is 32× smaller than input. The fix: transposed convolution (sometimes called deconvolution) for learnable upsampling, explained step-by-step with an interactive demo showing how a 2×2 input becomes a 4×4 output via a transposed conv. Why transposed convs cause checkerboard artifacts and the bilinear-upsampling-plus-1×1-conv alternative. FCN's skip connections from earlier higher-resolution layers (the precursor to U-Net's idea). A brief mention of dilated / atrous convolutions and the DeepLab family that followed.

U-Net — Interactive Explainer ↗
The architecture that dominated medical imaging and is now everywhere from segmentation to diffusion models. The U-shape laid out visually — contracting path (encoder: repeated conv + pool, double channels each level) on the left, expansive path (decoder: repeated upsample + conv, halve channels each level) on the right, and the symmetric skip connections that copy feature maps from encoder to decoder at matching resolutions. Why skip connections matter for segmentation specifically — the encoder loses spatial detail through pooling but gains semantic abstraction; the decoder needs both to produce precise pixel labels. An interactive demo showing the same image flowing through the U-Net with the skip-merged feature maps highlighted at each level. The original 2015 medical-imaging motivation (limited training data, need for precise cell boundaries). Why U-Net generalises to many domains — satellite imagery, document segmentation, audio spectrogram processing, and crucially as the denoising backbone of diffusion models (forward pointer to a future GenAI roadmap). Full PyTorch reference.

Mask R-CNN — Interactive Explainer ↗
Extending Faster R-CNN for instance segmentation — masks per detected object. The architecture as Faster R-CNN (callback to #17) + a parallel mask-prediction branch on each RoI. RoI Align as the key technical fix over RoI Pool — RoI Pool's coarse quantisation (rounding spatial coordinates) was tolerable for classification but destroyed pixel-level alignment for masks; RoI Align uses bilinear interpolation to sample features at exact subpixel locations. Self-Attention Intuition — Interactive Explainer ↗
The mechanism that makes Vision Transformers possible — built from zero for someone who's only ever seen convolutions. The motivation framed first — CNNs have local receptive fields (a 3×3 filter only sees its immediate neighborhood; you need many layers to "see" the whole image); what if every position in the image could attend to every other position from layer 1? That's self-attention. The Q / K / V mechanism explained as a soft database lookup — each token (image patch, in our case) creates a query ("what am I looking for?"), every other token creates a key ("what do I represent?") and a value ("what information do I carry?"). Attention weights = softmax(Q·Kᵀ / √d) — scaled dot product, where √d prevents the softmax from saturating in high dimensions (worked example showing how the variance scales). An interactive grid-of-patches demo where the user clicks a patch and sees the attention weights to every other patch visualised as opacity. Multi-head attention as running this in parallel with different learned projections, capturing different relationships. The output as a weighted sum of values. Computational cost — O(N²) in sequence length, a key trade-off vs CNN's O(N).

Positional Encoding — Interactive Explainer ↗
Why transformers need explicit position information, and how to give it to them. The problem — self-attention from #27 is permutation-equivariant: shuffle the input tokens, and you shuffle the output tokens but the model treats them as a bag, not a sequence / grid. Demonstrated with a side-by-side — same patches in different orders produce identical (shuffled) attention patterns. Two solutions: sinusoidal positional encoding (the original Transformer's approach) — fixed sin/cos functions of position at different frequencies, with the elegant property that relative positions can be computed by linear projections. An interactive visualisation of the sinusoidal encoding matrix and what each row "looks like." Learned positional embeddings (what ViT uses) — just a free parameter per position, learned during training. The trade-offs — sinusoidal generalises to longer sequences than seen in training; learned is more flexible. Brief mention of relative positional encodings (used in Swin, RoPE) and the 2D positional encoding specifically for image patches (separate row + column encodings). A worked example computing the embedding for a 4×4 patch grid.

The Vision Transformer (ViT) — Interactive Explainer ↗
The architecture that proved transformers work for vision — and how it processes an image. The radical idea — treat an image as a sequence of patches, run a standard transformer encoder on it, classify from a special token. Step by step — patch embedding: split a 224×224 image into 16×16 patches (= 196 patches), flatten each patch (16·16·3 = 768 numbers), linearly project each flattened patch to the model dimension. An animated visualisation of an image being patchified. The [CLS] token — a learnable extra token prepended to the sequence; its final representation becomes the image's classification embedding. Adding learned positional embeddings (from #28). Then N transformer encoder blocks (multi-head self-attention + MLP + layer norm + residual connections — every component a callback to a previous explainer). Final classification head on the [CLS] token output. The ViT-Base / ViT-Large / ViT-Huge family sized like BERT. The crucial result from the original paper — ViT matches or beats CNNs when pretrained on a very large dataset (300M images). Below ImageNet-scale, CNNs still win — motivating the next explainer.

Data-Efficient ViTs — DeiT — Interactive Explainer ↗
How to train a ViT on ImageNet alone, without needing 300M-image pretraining. The data-hungry problem from #29 stated as the puzzle DeiT solves. The DeiT recipe (Touvron et al., 2021) — strong data augmentation (RandAugment, MixUp, CutMix, repeated augmentation, with visual examples of each), regularisation (stochastic depth, label smoothing), and the key novelty: distillation token. Alongside the [CLS] token, add a [DIST] token trained to match the predictions of a CNN teacher (often a regnet or efficientnet). Why a CNN teacher works better than a transformer teacher (the CNN's inductive bias gets distilled in). Side-by-side training-curve plots — ViT alone overfits quickly on ImageNet, DeiT-with-distillation closes the gap with CNNs. DeiT's significance — it made ViTs accessible to anyone with a normal-sized training setup. A brief mention of DeiT-III as the modern recipe-refined evolution.

Hierarchical ViTs — Swin Transformer, Pyramid ViT & MViT — Interactive Explainer ↗
Bringing CNN-like multi-scale processing into the transformer paradigm. The motivation from #29 — ViT processes patches at one resolution throughout the network; there's no equivalent of CNN's pooling-driven multi-scale hierarchy, which is bad for dense prediction (detection, segmentation). Swin Transformer (2021) — the dominant fix: (a) shifted window attention: instead of global self-attention (O(N²) cost), compute attention only within local windows, and shift the window partition between alternating blocks so information eventually flows across windows. An animated visualisation of windowed vs shifted-windowed attention. (b) Patch merging: every few blocks, concatenate 2×2 neighboring patches and project to lower dimensions, mimicking CNN pooling. The result is a pyramid of feature maps at multiple resolutions — directly compatible with FPN-style detection heads (callback to #18). Pyramid Vision Transformer (PVT) as a parallel design — spatial-reduction attention to make global attention affordable at high resolutions. MViT (Multiscale ViT) for video and pooling-style attention. Comparison table — ViT vs Swin vs PVT vs MViT on detection / segmentation benchmarks.

Efficient ViTs for Edge — MobileViT, EfficientFormer & EdgeNeXt — Interactive Explainer ↗
ViTs on phones — what changes when compute budget is tight. The mobile constraint framed — standard ViTs need too much memory and FLOPs for phone-grade hardware. The shared design principle across this family — hybrid CNN-transformer blocks: keep MobileNet-style depthwise separable convs for cheap local feature extraction (callback to #14), insert lightweight transformer blocks for global mixing only where it pays off. MobileViT (Apple, 2021) — MobileNetV2 blocks for local + a small transformer block for global, interleaved. EfficientFormer (Snap, 2022) — dimension-consistent design to leverage hardware-friendly operations, MetaFormer-style decomposition. EdgeNeXt (2022) — split-depth-wise transpose attention, an efficient attention pattern that works on edge GPUs. EfficientViT briefly — cascaded group attention. A FLOPs-vs-accuracy Pareto plot comparing all of them against MobileNet baselines and full ViTs. When to reach for each on phones / Raspberry Pi / Jetson Nano. PyTorch reference using timm for pretrained checkpoints.

DETR & Successors — Transformer-Based Detection — Interactive Explainer ↗
Object detection without anchors, without NMS, end-to-end with a transformer. DETR (Carion et al., 2020) as the conceptual leap — a CNN backbone produces feature maps, those are fed into a transformer encoder-decoder, the decoder uses N "object queries" (learnable tokens, one per potential output box) that attend to image features. Each query directly produces a (class, box) prediction — no anchors, no NMS, no proposal stage. The bipartite matching loss — the predictions are matched to ground-truth boxes using the Hungarian algorithm so each ground truth is assigned to exactly one prediction; everything else is "no object." An animated demo showing query-to-image attention maps converging during training. DETR's significance — a fundamentally new detection paradigm. Its limitations — slow convergence (500 epochs!), worse small-object performance than YOLO. Deformable DETR (2021) as the fix — attention only attends to a small set of learned reference points, dramatically faster convergence. RT-DETR (2023) — real-time DETR variants that finally caught up to YOLO on speed-vs-accuracy. The set-prediction paradigm summarised.

SegFormer & Mask2Former — Transformer-Based Segmentation — Interactive Explainer ↗
Two important transformer-based segmentation models with different design philosophies. SegFormer (NeurIPS 2021) — the simple hierarchical approach: hierarchical transformer encoder (like Swin from #31, but with overlapping patches and no positional encoding — learned positional information emerges from a Mix-FFN), lightweight all-MLP decoder that fuses multi-scale features with no extra attention. Why removing the complex decoder works — most segmentation gain is from a strong encoder; the decoder just needs to fuse and upsample. The B0–B5 family from edge to server. Mask2Former (CVPR 2022) — the unified paradigm: one architecture for semantic, instance, AND panoptic segmentation. The key idea — instead of per-pixel classification, predict a set of mask queries (similar to DETR's object queries), each producing a class prediction + a binary mask. Masked attention restricts attention to the foreground of the predicted mask, dramatically improving convergence. A side-by-side visualisation of how the same Mask2Former handles all three segmentation tasks just by changing what queries mean. The unification trend in modern CV — one backbone, many tasks.

Self-Supervised ViTs — DINO & DINOv2 — Interactive Explainer ↗
Learning visual representations without labels — and getting object discovery for free. The motivation — ImageNet's 1.3M labels are expensive; the internet has billions of unlabeled images. Can we use them? DINO (Caron et al., 2021) — a self-distillation framework: two networks (student and teacher — same architecture, teacher's weights are a slow exponential moving average of the student's), fed two different augmentations of the same image, trained so the student matches the teacher's output. No labels needed. The crucial emergent property — DINO's attention maps on the [CLS] token spontaneously segment objects from background; a visualisation shows DINO discovering dogs and cars without ever being told what those are. The implications for object discovery and zero-shot segmentation. DINOv2 (Meta, 2023) — scaled to 142M curated images, multi-resolution training, distillation from ViT-g, producing universal vision features that work across classification, segmentation, depth estimation, and retrieval without task-specific fine-tuning. DINOv2's role as the de-facto vision backbone for downstream tasks in 2024–2026. The "vision foundation model" idea preview for Explainer #38.

Masked Image Modeling — MAE & BEiT — Interactive Explainer ↗
The "BERT for vision" approach to self-supervised pretraining. The masked-language-modeling analogy — BERT masks 15% of words in a sentence and trains the model to predict them; can we mask image patches and predict them? BEiT (Microsoft, 2021) — the first viable answer: tokenise image patches using a discrete tokenizer (like a VQ-VAE codebook), mask 40% of patches, predict the discrete token IDs of the masked patches. A worked example showing the masking and the per-patch token prediction. MAE (He et al., 2022) — the simpler, dominant version: mask 75% of patches (vastly more than NLP's 15% — images are more redundant), feed only the 25% visible patches to a heavy ViT encoder (computational savings!), then use a lightweight decoder to reconstruct the raw pixel values of the masked patches. Side-by-side reconstructions showing what MAE recovers from 25% visible. Why high mask ratios are necessary and why pixel-reconstruction loss works. The result — ViTs pretrained with MAE outperform supervised ImageNet pretraining when fine-tuned downstream. MAE's lasting impact on the SSL paradigm and its emergence as the default ViT pretraining recipe.

CLIP — Contrastive Language-Image Pretraining — Interactive Explainer ↗
The model that connected vision and language at internet scale, and gave us zero-shot image classification. The setup — 400M image-text pairs scraped from the web, two encoders (a ViT for images, a transformer for text), trained with contrastive loss: in a batch of N image-text pairs, the dot product of the i-th image embedding with the i-th text embedding should be high, and with every other text embedding should be low. An interactive batch-similarity-matrix visualisation showing the diagonal lighting up during training. The InfoNCE loss made concrete. Why this is powerful — at inference, you can classify an image against arbitrary class names by phrasing them as "a photo of a [class]" and picking the highest similarity. A live zero-shot classification demo where the user types arbitrary class candidates (no training data needed) and CLIP classifies an image among them. CLIP's downstream impact — it's the text-image bridge powering Stable Diffusion's text prompts, used as a frozen scoring model for image generation evaluation, and the conceptual ancestor of every vision-language model that followed.

BLIP & Flamingo — Vision-Language Models — Interactive Explainer ↗
Beyond CLIP's zero-shot classification — models that can generate captions, answer questions about images, and do few-shot multimodal in-context learning. BLIP (Salesforce, 2022) — a unified vision-language pretraining framework with three losses: image-text contrastive (like CLIP), image-text matching (binary "do they match?"), image-conditioned language modeling (caption generation). Why this multi-objective recipe produces a model that can both understand and generate. A live BLIP demo — upload an image → generated caption + Q/A on the image. BLIP-2 as the modern efficient version — connect a frozen image encoder + frozen LLM via a small trainable "Q-Former" bridge, dramatically reducing training cost. Flamingo (DeepMind, 2022) — few-shot multimodal in-context learning: feed the model a sequence of image-text-image-text examples in the prompt, then a new image, and it answers in the style of the examples without any fine-tuning. The cross-attention "Perceiver Resampler" that connects vision to a frozen language model. A worked example walking through a 2-shot VQA prompt. The lineage that led to GPT-4V and Claude with vision.

Segment Anything — SAM 1 → SAM 2 → SAM 3 — Interactive Explainer ↗
The Meta vision-foundation-model trilogy and its progression to open-vocabulary, video-aware concept segmentation. SAM 1 (Meta, 2023) — promptable image segmentation: user gives a click, box, or rough mask; SAM produces a precise segmentation mask for whatever object that prompt points at. Architecture — heavy ViT image encoder + lightweight prompt encoder + mask decoder. The SA-1B dataset (11M images, 1.1B masks, the largest segmentation dataset ever). The "segment anything" zero-shot capability demoed interactively. SAM 2 (2024) — extends SAM to video: the same prompt-based interface, plus mask propagation across frames using a transformer memory mechanism. Click an object in frame 1, get the tracked mask for the entire video. SAM 3 (2025–2026) — the open-vocabulary leap, Promptable Concept Segmentation. Instead of "this object" (a point), you say "all yellow school buses" (a text concept) and SAM 3 detects, segments, AND tracks every instance across an image or video. The hybrid architecture — a DETR-style detector + the SAM 2 tracker, both built on a shared vision-language Perception Encoder. A "presence head" that decides whether the concept exists at all before localising it. SAM 3 as the convergence point of everything in this roadmap — CNN + transformer backbones, transformer detection, transformer segmentation, vision-language alignment, self-supervised pretraining, video understanding. The natural endpoint for the CV journey.
