Pooling Strategies Explainer

by Ancil Cleetus

Convolution produces rich feature maps — but raw feature maps are enormous. Pooling is the operation that compresses them: keeping what matters, discarding what doesn't, and making the network faster, smaller, and more robust. There are three strategies, each with a different answer to the question "what do I keep?"

Why do we pool at all?

After a convolution layer you have a feature map — a rich grid of values showing where each pattern was detected. But feature maps are expensive. Consider what happens without pooling:

A 224×224 image passed through a layer with 64 filters produces 64 feature maps, each 224×224 = 3,211,264 values. That is just one layer. Without pooling, every subsequent layer operates on that full volume — quickly becoming computationally impossible.
Three reasons pooling exists
1
Spatial compression
Reduce the height and width of feature maps so later layers process far fewer values — making the network faster and cheaper to train.
2
Translation invariance
A cat ear detected at position (3,4) versus (3,5) still produces the same pooled output — the network stops caring exactly where a feature appears, only whether it appears.
3
Expanding receptive field
After pooling, each cell in the next layer's feature map "sees" a larger region of the original image — allowing deeper layers to detect larger structures without adding parameters.

Max pooling — keep the loudest signal

How it works: Divide the feature map into non-overlapping rectangular windows. Inside each window, keep only the largest value and discard the rest. The output is a smaller grid of those maximum values.

Why keep the maximum? Because in a feature map, a high value means "this filter detected its pattern strongly here." Keeping the maximum preserves the strongest detection in each region — even if the exact location shifts slightly.

Where max pooling excels: It is ideal for tasks where you care about whether a feature is present, not where exactly it is. This includes detecting edges (a strong edge response anywhere in the window survives), corners, textures, and other sharp localised patterns. For this reason, max pooling is the default choice in most image classification and object detection networks.
MaxPool(i, j) = max(window at position i, j)
For a 2×2 window at row i, col j: MaxPool(i,j) = max(f[2i][2j], f[2i][2j+1], f[2i+1][2j], f[2i+1][2j+1])

Gradient note: During backpropagation, only the cell that produced the maximum receives the gradient. All other cells in the window receive a gradient of zero — they had no influence on the output, so the network does not adjust them for this pool window.

Average pooling — take the average signal

How it works: Same idea as max pooling — divide into windows — but instead of keeping the maximum, compute the average of all values in each window. Every cell contributes equally; no single value dominates.

Average pooling is gentler than max pooling. It is better at preserving diffuse features — background texture, overall colour tone, gradual gradients — where no single pixel stands out but the average signal is meaningful.
AvgPool(i, j) = (1 / (p×p)) × Σ values in window at position i, j
For a 2×2 window: AvgPool(i,j) = (f[2i][2j] + f[2i][2j+1] + f[2i+1][2j] + f[2i+1][2j+1]) / 4

Global average pooling — collapse the entire map

How it works: Instead of pooling small windows, average every value in the entire feature map into a single number. One feature map of any size → one scalar. 512 feature maps → 512 scalars.

Global average pooling (GAP) is not a spatial compression step — it is a complete spatial collapse. It is used as the final step before the classification layer in modern CNNs, replacing the old Flatten + Dense approach.
GAP(channel k) = (1 / (H×W)) × Σ all values in feature map k
H = height, W = width of the feature map. The result is one number per channel — the spatial average activation of that filter across the entire image.
Why GAP instead of Flatten + Dense?
Old approach — Flatten + Dense
512 maps × 7×7 = 25,088 values → flatten to a 25,088-long vector → Dense layer with millions of parameters. Prone to overfitting. Input size must be fixed.
New approach — Global Average Pooling
512 maps × 7×7 → one average per map → 512 values. Tiny, robust, works with any input size. Used in ResNet, MobileNet, EfficientNet.

Decision guide — which pooling to use
🎯 "I want to detect whether a feature is present anywhere in a region"
Max pooling — keeps only the strongest activation. If the feature fires even once in the window, it survives. Ideal for edge detection, texture detection, sharp localised patterns.
🌊 "I want to measure the average intensity or texture across a region"
Average pooling — every cell contributes equally. Preserves diffuse, spread-out signals. Sometimes used in attention mechanisms and in some branches of inception modules.
🏁 "I need one final summary number per channel before classification"
Global average pooling — completely collapses spatial dimensions. Modern default for the final reduction step. Used in ResNet, MobileNet, EfficientNet, and most architectures published after 2015.

Spatial compression — the numbers

Every 2×2 max pool with stride 2 halves the height and width — quarter the spatial area. Through a typical CNN with multiple pooling stages, the feature map shrinks dramatically. See the exact numbers for a real architecture.

Parameters
The learned weights of the network — filter values, classifier weights, biases. Fixed per architecture, independent of input image size. Pooling does not directly reduce parameters.
Activations
The intermediate tensors — the feature map values flowing through the network during a forward pass. These depend on input size and grow with image resolution. Pooling directly reduces activations.
